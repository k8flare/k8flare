# clientgo-lean-overlays

Second local module mirror, alongside `pkg/k8s-js-overlays/`: this
one prunes `k8s.io/client-go` instead of patching `k8s.io/kubernetes`.
Generated by `scripts/gen-clientgo-lean-mirror.sh` into
`.build/clientgo-lean-mirror/` (gitignored, not committed -- same reasoning
as the sibling k8s-js-mirror).

## Why this exists

`pkg/leanclient` (the hand-written verb/watch helpers replacing client-go's
generated Get/List/Watch/etc.) still has to satisfy client-go's _own_,
externally-fixed interfaces (`corev1.PodInterface` and friends) --
upstream controller code (`pkg/controller/*`, `pkg/scheduler`, real and
unmodified per CLAUDE.md rule 3) requires its client parameter's static
type to be exactly `k8s.io/client-go/kubernetes.Interface`. Two problems
with importing those interfaces from the real, unpruned `k8s.io/client-go`
module:

1. **`Apply`/`ApplyStatus`, required by every `XInterface` even though
   this repo's controllers never call Server-Side Apply (confirmed by
   grep -- zero hits)**, take a parameter of type
   `k8s.io/client-go/applyconfigurations/<group>/<version>.XApplyConfiguration`.
   Referencing that type -- even in a signature that's never invoked --
   costs ~40MiB of linked GOOS=js/wasm code. Verified (not assumed) to
   have nothing to do with the referenced type's own complexity: emptying
   `PodApplyConfiguration` to a bare `struct{}` changed nothing; deleting
   the ~200 _unrelated_ sibling files in the same
   `applyconfigurations/core/v1` package (ServiceApplyConfiguration,
   ConfigMapApplyConfiguration, ...) dropped an identical probe from
   44.25MiB to 2.04MiB with zero other changes. Go links some or all of a
   package's sibling declarations once _any_ symbol from that package is
   referenced, regardless of reachability from `main()` -- the mechanism
   isn't fully root-caused, but the fix (prune unrelated siblings) is
   empirically confirmed.
2. The same issue reproduces one layer up: merely referencing
   `k8s.io/client-go/kubernetes/typed/core/v1.PodInterface` (an interface
   declaration, not a concrete client) costs the same ~44MiB, because that
   package's `pod.go` itself imports `applyconfigurations/core/v1` for
   `PodInterface`'s `Apply` signature, and `typed/core/v1` has its own ~20
   sibling files (one per core/v1 type -- ConfigMap, Secret,
   PersistentVolume, ...) with the identical problem.

`go build -overlay` cannot fix either of these: `k8s.io/client-go`
resolves via this repo's `replace` into `GOMODCACHE`, and overlay refuses
to touch anything there (see `pkg/k8s-js-overlays/README.md` for
the exact error and why -- same restriction, same reason). The only lever
is a module-level `replace` to a local, generated, pruned copy.

## What's pruned, and how

**Correction (2026-07-08, matching `docs/platform-verification.md`'s
"Phase 10" note): per-type pruning of `kubernetes/typed/<group>/<version>/`
and `applyconfigurations/<group>/<version>/` was tried and abandoned.**
It broke the moment `pkg/scheduler.New`'s `informerFactory` parameter
(fixed to the real, unmodified `k8s.io/client-go/informers.
SharedInformerFactory`, which imports all ~54 groups' typed/
applyconfigurations packages directly in its own `factory.go`) entered the
same binary -- those packages cross-reference each other extensively
(e.g. autoscaling's `HorizontalPodAutoscalerApplyConfiguration`
references core's `ObjectReferenceApplyConfiguration`), so partial
pruning cascades into compile errors across unrelated groups. The
per-type overlay files this repo carried for those two directories (and a
`listers/` overlay attempt) were only ever kept "for the record" per
`scripts/gen-clientgo-lean-mirror.sh`'s own comment, were never actually
copied into the generated mirror, and have since been deleted --
`docs/platform-verification.md`'s Phase 10 section is the durable record
of why. What's actually pruned today, still real and load-bearing:

- **`kubernetes/clientset.go`**: `Interface` is narrowed from ~54 group
  accessors to the 5 this repo uses. See that file's own doc comment for
  why this (not implementing the full 54-method interface with panic
  stubs, an earlier spike's approach) is both simpler and sufficient.
- **`kubernetes/scheme/register.go`**: registers only the group-versions
  the wasm control-plane binaries actually serialize, instead of
  upstream's ~55 (its own doc comment covers why -- discovery pulled in
  ~21MiB of generated API-type code otherwise). Drift-checked against
  upstream via `upstream-scheme-register.go.sha256`.
- **`informers/factory.go`**: `SharedInformerFactory` pruned to the 5
  groups the real, unmodified upstream `kube-scheduler` actually calls
  (nothing _external_ requires the other 49, unlike `kubernetes.Interface`
  and the per-group informers themselves, which is exactly why those stay
  full width). Drift-checked via `upstream-informers-factory.go.sha256`.
- Every other directory in `k8s.io/client-go` (rest/, tools/cache/,
  the per-group `informers/<group>/<version>/`, `listers/`, discovery/,
  ...) is untouched -- a full APFS clone, not copied by hand.
  `pkg/leanclient`'s watch/verb helpers and the informer/lister wiring
  (`pkg/controllers`) both depend on this being real, unmodified upstream
  code (CLAUDE.md rule 3).

## Regenerating

```
scripts/gen-clientgo-lean-mirror.sh
```

Same operational note as `pkg/k8s-js-overlays/`: `go.mod`'s
`k8s.io/client-go` replace points at the generated
`.build/clientgo-lean-mirror/`, which must exist before _any_ Go build in
this repository works, not just the WASM one. `npm run build:wasm`
regenerates it automatically; run this script by hand first for a
host-only build in a fresh checkout.

Both remaining pruned files are drift-checked the same way as
`pkg/k8s-js-overlays/`: the generator compares each upstream
source file's sha256 against `upstream-scheme-register.go.sha256` /
`upstream-informers-factory.go.sha256` and fails loudly if upstream moved,
rather than silently shipping a stale overlay. A k8s/client-go version
bump that fails one of those checks is the signal to review the new
upstream file and refresh the overlay + its `.sha256` pin.
