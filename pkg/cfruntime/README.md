# cfruntime

The Go/WASM &lt;-&gt; Cloudflare Workers runtime bridge (fetch event dispatch,
env binding access, outbound `fetch()`, and the `wasm_exec.js` bootstrap
that loads a Go WASM module into the Workers `js`/`wasm` runtime). Used by
every WASM entrypoint in this repo (`cmd/apiserver-wasm`, `cmd/kcm-wasm`,
`cmd/kcm-wasm/scheduler`) and by `pkg/controllers/restconfig.go`.

## Origin

Absorbed 2026-07-08 from [`github.com/syumai/workers`](https://github.com/syumai/workers)
v0.32.0 (MIT, see `LICENSE.md`), previously vendored as a patched fork at
`third_party/syumai-workers-fork/` and referenced via a `go.mod` `replace`.

This is **not** an upstream-k8s/k3s dependency (CLAUDE.md rule 3, "prefer
real upstream over reimplementation," is about the Kubernetes ecosystem
specifically) -- it's Cloudflare Workers platform glue, which is squarely
this project's own domain. The fork already carried a local patch (a
`sync.Once` guard in `handler_js.go` fixing a `doneCh` double-close panic
that upstream's one-request-per-instance assumption doesn't hit, but this
project's resident-WASM-instance execution model does -- see
`docs/platform-verification.md`'s S8 section), so tracking a local
divergence from upstream indefinitely was already the reality; absorbing
it removes the indirection (external module replace, a second go.mod
entry, a 384KB vendored copy of files this project doesn't use) without
losing anything, since further Worker-runtime-specific fixes are exactly
the kind of change that belongs here rather than upstream anyway.

## Scope

Only the subset this repo's binaries actually import: `Serve`/
`ServeNonBlock`/`Ready` (`handler.go`, `handler_js.go`), `Getenv`/
`GetBinding`/`WaitUntil` (`cloudflare/`), and the outbound-fetch client
(`cloudflare/fetch/`, imported as `cffetch`). Upstream's `cloudflare/d1`,
`cloudflare/queues`, `cloudflare/kv`, `cloudflare/r2` (this repo signs R2
requests itself, see `pkg/apiserver/r2.go`), `cloudflare/cache`,
`cloudflare/sockets`, `cloudflare/cron`, `exp/hono`, and the
`cmd/workers-assets-gen` tool were not carried over -- `wasm_exec.js` is
committed directly here instead of regenerated by that tool on every
build.

## Updating

Not regenerated by any script -- these are now plain, hand-maintained Go
files like the rest of this repo. A future upstream fix worth pulling in
should be re-applied by hand (the surface is small enough that a diff
against a fresh `go mod download github.com/syumai/workers@latest` is
tractable) rather than restoring the fork/replace indirection.
